# Post-Review Changes — Infrastructure Design, U2 Session Security

The files in this folder stay exactly as reviewed (iteration 1, READY; `reviews/review-01.md`). This note amends them. All decisions here are **[Decided by delivery team]**.

| Finding | Change |
|---|---|
| R-01 Checkpoint time budget | Decided now, not left as a contingency.<br>**`scripts/verify-skeleton.sh` (the checkpoint command, about 2-minute limit) runs a fast subset at the desktop viewport only:**<br>- `skeleton.spec.ts` (U1 journey);<br>- `session.spec.ts` tagged `@checkpoint`: reload stays signed in; two tabs refresh together; logout in one tab signs out the other; forgot → Mailpit code → reset → login.<br>**The full matrix runs in CI (`e2e` job) and in `bash scripts/verify.sh`:** both viewports, every session scenario, and axe on every screen.<br>**Time budget:** the subset must finish in 110 s or less end to end. The script prints the elapsed time and fails with a clear message above 110 s, so a slow machine shows up before the verifier's hard limit. |
| R-02 Rate limits in tests | `scripts/ci-env.sh` sets `AUTH_RATE_LIMIT_PER_MINUTE=1000` and `REFRESH_RATE_LIMIT_PER_MINUTE=1000` for the test environment only, with keep-if-set behaviour. The production defaults (20 and 60) are unchanged. The limiter's own tests set the low limits explicitly, so throttling stays covered. |
| R-03 SameSite setting | `REFRESH_COOKIE_SAMESITE` defaults to `lax` (allowed: `lax`, `strict`, `none`). The validator refuses `none` unless `REFRESH_COOKIE_SECURE=true`. `AUTH_RATE_LIMIT_PER_MINUTE` (20) is inherited from U1 and listed alongside the U2 settings in the README configuration table. |
| R-04 CI file lists | `.github/workflows/ci.yml` is edited as follows:<br>- the perf step adds `tests/identity/test_perf_enumeration.py` and the U2 endpoint perf tests;<br>- the Playwright step runs `e2e/skeleton.spec.ts e2e/session.spec.ts`;<br>- the failure artifact upload already captures the whole `playwright-report/` and test results. |
| R-05 `EMAIL_HASH_KEY` placeholder | `backend/.env.example` holds `EMAIL_HASH_KEY=change-me` (9 bytes). The settings validator rejects any value shorter than 32 bytes, naming the setting but never the value, so the placeholder can never run. `ci-env.sh` generates a key only when none is set. |
| R-06 Traceability | NFR2.17 maps to `CSRF_ALLOWED_ORIGINS` (infrastructure specification, new configuration) plus the CORS preflight tests in the backend job. NFR9.9 maps to the accessibility suites in the frontend job and to the axe run in the e2e job. This note is their trace record; `traceability.json` is not edited after review. |
